# Galeria de catálogo

Modelo estático sem autenticação. `index.html` lê `catalog.public.json` a cada visita: atualizar dados ou capas não exige recompilar o APK. O exemplo começa vazio para não atribuir licenças ou direitos a jogos sem revisão.

No Manager, sincronize o catálogo ou escolha a pasta local e abra **Catálogo GitHub**. Revise os campos: `publicSelected` e `redistributable` precisam ser marcados explicitamente; `category` aceita `homebrew`, `demo` ou `public-domain`; `license` é obrigatória. Esses campos registram a revisão humana, não uma verificação automática de direitos. Use **Exportar público** para gravar `catalog.public.json`. A exportação usa uma lista de campos permitidos, descartando caminhos privados e credenciais. Capas autorizadas devem ser copiadas manualmente para `assets/` e referidas como `assets/nome.png` (também JPG, JPEG ou WebP). Não copie pastas inteiras da biblioteca.

Links são opcionais: `publicDownload` aceita uma página HTTPS pública, sem credenciais, parâmetros ou endereço IP, e exige `downloadPublicConfirmed=true`. Confirme que a página e o conteúdo são públicos e redistribuíveis. Não coloque arquivos ROM, saves ou binários neste site. Downloads diretos de ROM ou arquivo compactado são rejeitados nesta fase.

Para a biblioteca privada, salve um token de leitura do repositório no Manager. Ele fica protegido por DPAPI do usuário Windows no cache local. A API confirma que o `origin` é privado; o push usa a credencial Git configurada separadamente. Selecione um checkout limpo, externo ao projeto público, com `origin` apontando ao mesmo repositório GitHub na leitura e no push. **Publicar privado** pede confirmação, grava apenas `catalog.private.json`, cria commit e envia a branch atual. Não transfere ROMs. Falhas de Git podem deixar o catálogo ou commit local pendente; revise e conclua a operação no Git antes de repetir. Nenhum repositório é criado automaticamente.

Para publicar a galeria, escolha o repositório Pages, inclua `catalog-site/`, `manager-windows/GitHubCatalog.ps1`, `scripts/Test-PublicLayout.ps1` e o restante do layout esperado pela auditoria, ou adapte a auditoria ao checkout dedicado. Habilite GitHub Pages com GitHub Actions. Exporte pelo Manager o catálogo público revisado para `catalog-site/catalog.public.json` no checkout Pages configurado; depois faça commit e push desse arquivo e das capas autorizadas para `main`. O Manager grava o JSON público; o commit/push público é feito pelo Git ou por uma automação externa configurada para esse checkout. Cada push em `main` dispara automaticamente **Publish catalog Pages**, que verifica o layout e envia somente `catalog-site/`. A opção manual **Run workflow** continua disponível para republicar. A URL real é fornecida pelo ambiente `github-pages` após o deploy. Esta implementação não cria repositório nem publica durante os testes.

Teste a galeria por um servidor HTTP estático local; abrir o arquivo por `file://` pode impedir a leitura do JSON. Busca, filtro, estado vazio, falha de rede e fallback de capa funcionam sem serviço de aplicação.
